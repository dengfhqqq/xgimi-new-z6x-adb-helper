# 使用教程

## 1. 先确认是否适用

本工具只在 NEW Z6X、Android 8.0.0、`ironman / v12.15.180` 上验证过。配置操作还会核对完整 fingerprint。名称相近的普通 Z6X、其他系统版本和其他极米型号均不在已验证范围内。

电脑与投影仪需要在同一可信局域网，并允许设备之间通信。无需接 USB 工程线。应用不修改监听端口：本次已验证固件原有端口属性为 `5555`，若你的报告是空值或其他值，请保存诊断，不要自行假设同样可连。

本工具调用固件已有服务准备配置和启停 daemon，不刷机，不获取 root。配置保护拒绝操作时应保留报告，不能通过改代码跳过校验来证明兼容。

## 2. 安装 APK

1. 从你信任的发布来源取得 APK，并核对该次发布提供的 SHA-256。
2. 使用 U 盘或投影仪支持的文件传输方式把 APK 送入设备，用文件管理器安装。系统要求时允许该安装来源。
3. 打开“Z6X ADB 助手”。可用遥控器方向键与确认键，也可用 USB 鼠标。
4. 等自动检测结束，再选择“刷新状态”。应用打开和检测本身不请求修改 ADB 配置。

老版本用户应优先使用同签名的覆盖安装，保留应用私有数据。不要为解决签名不一致随意卸载：原始配置备份保存在应用数据里，卸载或清数据会丢失它。

## 3. 第一次启用：按顺序完成

### 第一步：读取当前状态

先检测，关注：

| 项目 | 含义 |
| --- | --- |
| 设备与完整 fingerprint | 是否是已核实固件 |
| `persist.sys.usb.config` | 持久调试配置；本工具只接受精确 `none` 或 `adb` |
| `adb_enabled` | framework 的调试标记；与 daemon 进程是两层状态 |
| `init.svc.adbd` | ADB 服务是否 `running` 或 `stopped` |
| `service.adb.tcp.port` / `persist.adb.tcp.port` | 运行中的 daemon 使用的端口属性；有值不代表已启动 |

初始持久配置是 `none` 时进入第二步。若已是 `adb`，应用不会覆盖原始备份或虚构备份，先读本教程“后续使用”。

### 第二步：准备调试配置

1. 选择 **准备调试配置（需重启）**。
2. 查看当前值与目标值，确认设备符合支持范围。可以取消，取消不写配置。
3. 确认后，应用会重新绑定服务和读取状态；配置变化、身份不符或备份保存失败都会停止。
4. 应用先将原始 `none` 配置和设备标识同步保存到私有数据，再请求目标 `adb`。
5. 等回读完成，必须看到 `persist.sys.usb.config` 与目标 `adb` 精确匹配。只有“请求已返回”不够。

请求失败或回读不匹配时，先复制或导出报告，不要重复点击、拔电或尝试其他未知属性。

### 第三步：正常重启

确认持久值为 `adb` 后，使用投影仪正常重启方式；应用不会替你发出重启命令。重启是为了让系统重新初始化调试与授权状态。只退出应用再打开不等于系统重启。

系统完全启动后，重新打开助手并检测。已验证的重启后组合为：

```text
persist.sys.usb.config=adb
adb_enabled=1
sys.usb.config=mtp,adb
sys.usb.state=mtp,adb
init.svc.adbd=stopped
```

这里 `mtp,adb` 是原厂系统自动选择的运行配置，不是应用直接写入的结果。它不证明物理 USB 已连接。

### 第四步：按需启动 ADB 服务

在持久配置为 `adb`、`adb_enabled=1` 且服务为 `stopped` 时，选择 **启动 ADB 服务**，读完确认框后确认，等状态回读。

服务已是 `running` 时直接在电脑连接，不必停止再启动。单独启动服务不等于准备了完整调试状态；初始 `none + adb_enabled=0` 时，曾出现端口开放但一直 `unauthorized`。

### 第五步：电脑实际连接

电脑安装 Android SDK Platform-Tools，在投影仪网络设置查看当前 IP，将命令中的占位符替换成该地址：

```bash
adb connect <投影仪IP>:5555
adb devices -l
adb -s <投影仪IP>:5555 shell id
```

不要把尖括号原样输入命令。成功标准是设备状态为 `device`，且指定目标的命令能够返回。已验证输出权限为 `uid=2000(shell)`，不是 root。

这个固件的新公钥处理路径会自动允许主机，可能完全不弹标准 RSA 授权框。不要把“没有弹窗”当成未开启的证据；也不要因此把设备放到不可信网络。

## 4. 后续使用与正常停止

每次系统重启后先检测。持久配置仍为 `adb` 且 `adb_enabled=1` 时，服务已运行可直接连接；服务停止才选择 **启动 ADB 服务**。不必每次重新“准备调试配置”。更多重启后的自启动表现尚未重复验证。

本次用完要暂时停止服务，可选择 **停止 ADB 服务**并确认，再从电脑检查连接是否断开。它不恢复持久配置、不删除主机密钥，也不能保证其他系统逻辑以后不会再启动服务。

电脑端的 `adb disconnect` 只断开电脑连接，不会关闭投影仪 ADB 服务。

## 5. 恢复原始配置

1. 保留应用数据；先检测并复制当前报告。
2. 选择 **恢复原始配置**。仅当应用仍保存了本次设备的有效原始 `none` 备份时允许继续。
3. 检查确认框中的当前值、目标 `none` 和原始备份信息。无备份、设备不符或值未知时应用会拒绝写入。
4. 确认后等待目标 `none` 的精确回读，再自行正常重启。
5. 重启后检测，并在电脑检查端口/ADB 是否已关闭；不要只凭按钮完成提示认定关闭。

已验证到恢复预检与确认框，尚未实测完整恢复、重启及关闭的全过程。恢复只写回该原始配置，不清除已保存的 `adb_keys`，不等于撤销主机授权，也不保证网络 ADB 立即关闭。需要暂时停止运行服务时，可另行使用 **停止 ADB 服务**，它不会由恢复流程自动附加执行。

若应用安装前持久值就已是 `adb`，且没有本应用保存的原始备份，应用会显示“已配置”，不会凭空创建一个 `none` 备份。请勿清数据后期待恢复功能仍有原值。

## 6. 常见问题

| 现象 | 下一步 |
| --- | --- |
| 设备/固件不支持，或当前值未知 | 停止配置操作，保存报告；本工具只验证一个固件，不绕过校验 |
| 绑定服务失败、超时或接口不匹配 | 等系统正常启动后再检测一次；仍失败则保留报告，不试猜测的事务号 |
| 配置请求返回，但目标回读不匹配 | 视为未确认写入成功，保存完整报告；不要按成功流程重启 |
| `adb_enabled=0` 且只启动过服务 | 从首次流程核对持久配置、目标回读和正常重启，启动 daemon 本身不够 |
| 重启后 `adb_enabled=1`、持久值 `adb`，服务 `stopped` | 选择“启动 ADB 服务”，然后电脑连接 |
| `Connection refused` | 检查当前 IP、同一局域网、端口和服务状态；不是 RSA 弹窗问题 |
| `unauthorized` | 先核对调试标记、持久配置和是否真正重启；此固件可能没有弹窗。确认状态后重新连接，仍异常就保留报告 |
| 连接超时 | 检查网络隔离、访客 Wi-Fi、IP 变化或电脑防火墙；端口属性不是连通性证明 |
| 状态 `device`，但命令执行在另一台设备上 | 每条命令加 `-s <投影仪IP>:5555` 指定目标 |
| `sys.usb.state` 含 `adb`，USB 却断开 | 属性不等于物理枚举。先用网络 ADB；本项目未验证 USB 工程线可用 |
| 导出 TXT 被拒绝 | 允许存储权限，或查看应用提示的备用目录；也可复制诊断全文 |
| 卸载后没有恢复备份 | 私有数据已随卸载删除；本工具不能推测安装前的原始配置 |

## 7. 分享报告与源码

复制或导出前先确认正在显示的是你要分享的那次报告。应用不主动上传任何内容。公开发帖前检查报告中的设备标识、时间、文件位置及你后来补充的网络地址，按需删去个人信息。

仅在可信局域网临时使用 ADB，不在路由器映射或公开暴露 5555。ADB 已授权主机可以执行 shell 命令；恢复配置不会删除该授权。分享源码时不要附带签名私钥、设备日志、官方固件、厂商 APK 或反编译产物。
